# Minimalist Android UI：C 版落地規格

狀態：**使用者已確認設計、落地範圍與測試 seam；正式 Android 尚未依本規格實作、驗收。**

實作 Issue：[GitHub #11 — Minimalist C 版正式 Android UI 與點按語音操作](https://github.com/DaDioDa/TalkToAgent/issues/11)，標記 `ready-for-agent`。完整使用者故事與測試決策已發布於該 Issue。

## 目標與文件界線

將已選定的 C 版操作方式落地到正式 Android App，接上真實語音辨識與電腦貼上流程。本輪先完成操作、資訊層級與按鈕佈局；保留灰階，美術風格另行處理。

- 核心使用情境：個人日常使用，左手持手機，眼睛主要看電腦。
- 極簡代表清楚且直接，不為了藏按鈕而增加常用操作步驟。
- 定案的是**下半部大觸控區＋最底部全寬取消列**，不是初版 C 的右下角小取消鈕。
- 原型及已完成的瀏覽器檢查見 [原型 README](prototype/uiux/README.md)。網頁模擬不是正式程式，也不是原生手感或真實收音驗收證據。
- 領域詞彙以 [CONTEXT.md](../CONTEXT.md) 為準。本規格不新增 glossary 名詞，也不另建可逆 UI 版面的 ADR。
- 本規格是後續實作的目標；實作完成前，[Android 語音文件](android-voice.md) 與程式中既有按住／放開操作不代表已變更。

## 變更與保留範圍

本次正式變更：

1. 用 C 版替換正式主畫面的操作與資訊配置。
2. 按住／放開改成點一下開始、再點一下結束；轉錄定稿後自動傳送，不增加日常確認步驟。
3. 新增準備中／收音中可用的獨立全寬取消列與原生觸覺回饋。
4. 將現有 45 秒期限的「超時中止且不傳送」改為「到限正常結束收音，取得有效定稿後傳送一次」。
5. 重整連線、設定、最近定稿與診斷入口，不移除既有能力。

保留既有範圍及協定，參照 [Android 語音文件](android-voice.md)、[QR 驗收](qr-acceptance.md)、[藍牙決策](adr/0001-direct-bluetooth-input.md)、[QR 授權決策](adr/0002-qr-persistent-authorization.md) 與 [Receiver 說明](../windows_receiver/README.md)：

- 不重做傳輸／授權協定，不新增自動連線、重送或撤回貼上功能。
- 既有 Wi-Fi 每連線一次傳送及藍牙工作階段行為保留；不能為了呈現連續可用的 UI 假裝連線仍就緒。Wi-Fi 傳送後如需再次連線，由連線入口操作。
- 保留 QR 邀請、既有應用授權續接、通道選擇、主動中斷與既有金鑰／權限管理能力；不要退回歷史文件中的手動 IP／配對碼介面。
- 保留定稿的繁體字形處理、有效性檢查與既有辨識收尾規則；不把暫時辨識文字當定稿傳送。
- 沒有背景收音、背景完成辨識的新能力，沒有逐字稿歷史。
- 保留既有資料與憑證，不因 UI 改版清除設定、應用授權或要求卸載 App。

## 畫面配置

### 主畫面

- 直向優先，主畫面固定直向；本輪不設計橫向專用操作版面。
- 上方顯示精簡電腦名稱／連線狀態；另清楚顯示整體輸入狀態與必要原因，不能將「電腦已連線」等同「輸入就緒」。
- 下半部是大面積的開始／結束觸控區。
- 最底部是左右貫通的全寬取消列，與主區有明確間隔及獨立觸控範圍，不得重疊。
- 原型的 68px 取消列與 12px 間隔是視覺參考，不是直接套用為 Android 實體像素。正式尺寸須依可觸及性與真機檢查驗收。
- 取消列位於 Android 系統導覽／手勢安全區上方，不覆蓋系統操作區。
- 主觸控區與取消列位置固定，不隨狀態文字、內容捲動或停用而跳動。取消不可用時保留位置並清楚停用。
- 小螢幕先縮減上方留白；不能靠捲動才能找到結束／取消。必要狀態文字及控制仍須可讀、可點。

### 次要入口

- 點電腦／連線狀態開啟連線管理；配對與通道控制不常駐首頁。
- 設定容納金鑰等低頻設定；手動文字輸入只放在「設定 → 診斷與手動測試」。
- 最近轉錄定稿預設隱藏，提供明確入口查看與手動複製。只保留既有目前畫面暫留的一段，不增加持久歷史，也不因查看而再傳送。
- 設定、連線與診斷內容可捲動。
- 準備、收音、等待定稿及傳送期間，暫停連線、設定、最近定稿等次要入口，避免面板遮住當前狀態或中途改設定。

## 操作狀態

| 階段 | 主觸控區 | 底部取消列 | 語意 |
|---|---|---|---|
| 輸入就緒 | 點一下開始 | 停用、保留位置 | 必要條件具備，不保證此次 Gemini 辨識成功 |
| 尚未就緒 | 不得開始收音；顯示原因 | 停用 | 提供對應的修復入口 |
| 準備中 | 顯示準備中、停用 | 可取消 | 正在連線／準備麥克風，尚不能宣稱已收音 |
| 收音中 | 點一下結束並送出 | 可取消 | 真正收音後才提示可以說話 |
| 等待轉錄定稿 | 停用 | 停用 | 等待有效定稿，未完成前不可再開始或重複提交 |
| 傳送中 | 停用 | 停用 | 已進入傳送，不能宣稱可撤回貼上 |
| 貼上操作完成 | 就緒條件成立即可開始新段 | 停用 | 只表示電腦發出貼上操作，不保證目標程式接受文字 |
| 已取消／辨識失敗 | 就緒條件成立即可開始新段 | 停用 | 顯示取消或失敗原因，不自動重試 |
| 輸入結果不明 | 就緒條件成立可主動開始新段 | 停用 | 保留警告，不自動重送，不額外要求確認按鈕 |

操作結果與就緒條件必須分開判斷：例如結果不明且已斷線時，不能直接開始新收音；恢復連線也不能清掉尚未處理的結果不明警告。警告保留到使用者主動開始新段，開始的是新輸入，不是重試上一段。

金鑰缺失／無效、麥克風未授權、Receiver 未驗證與其他已知故障，不得只留下灰色按鈕而沒有原因及修復入口。修復條件後仍由使用者主動開始，不因權限彈窗返回而自動收音。

## 時間、亮屏與輕震

- 啟動本次語音流程起算 **45 秒**，包含連線準備時間；不是麥克風啟動後另給 45 秒。
- 準備及收音期間顯示剩餘時間，不能用「已錄音時長」誤導使用者。
- 真正開始收音時一次輕震；正常結束收音時一次輕震。不在剛收到開始點擊時假裝已收音。
- 期限剩 **5 秒**時短促雙震，配合文字提醒即將自動結束並送出；沒有提示音。
- 收音到限時走與手動結束相同的收尾、定稿及單次傳送流程，不直接把尚未定稿的內容送出。沒有有效定稿、辨識失敗或定稿逾時，仍不得傳送。
- 保留既有初始化及定稿等待失敗邊界，不因到限自動送出而繞過檢查；初始化失敗就終止本次，不等待 45 秒強行提交，也不自動重試。
- 到限後不是自動開啟下一段，也不提供連續分段收音。
- 收音期間保持螢幕亮著，結束／取消／失敗後解除該要求；不更改系統全域熄屏設定。手動鎖屏仍適用下節的取消規則。
- 系統不允許或裝置不支援觸覺回饋時，視覺狀態仍完整可用；瀏覽器模擬輕震不算原生驗證。

## 取消、離開與競爭事件

- 準備中或收音中按取消，停止本次流程並丟棄其輸入，不送往電腦。不得把「取消」實作為正常結束並送出。
- 收音／準備期間切 App、按 Home、退出畫面或鎖屏，取消本次、不傳送；回到畫面須可辨識本次已取消，不自動恢復收音。
- 已點結束但仍等待定稿時離開，同樣取消尚未送出的本次內容。
- 已送往電腦的內容不能撤回：離開、斷線或關閉畫面都不能將其偽裝成「取消且未送出」。已有可信結果則保留該結果，無法確認則顯示「輸入結果不明」。不新增持久歷史要求。
- 準備／收音期間 Receiver 失去驗證，沿用中止本次、不自動補送的行為。
- 手動結束、45 秒到限、取消、生命週期離開及晚到的辨識回呼可能相遇；每段最多只能提交一次。已取消的舊段不得藉晚回呼觸發傳送或更改新段狀態。
- 本規格不要求特定類別拆分，但實作與測試必須能區分準備、實際收音、等待定稿及已送出，不能把按下開始一律當作正在收音。

## 驗收條件

### 已確認的測試 seam

採用**單一語音流程協調 seam＋少量 Android 整合／真機驗收**。優先深化既有口述流程的 interface，由正式 Activity 與測試共同使用，集中處理準備、實際收音、時間期限、取消、離開與晚回呼；不為每個按鈕或計時器增加零散測試 seam，也不另寫只供測試的平行狀態機。

測試控制時間及外部辨識／傳輸事件，驗證可觀察狀態與送出的文字／訊息次數，不驗證私有欄位或內部方法呼叫。保留既有定稿、就緒、繁體轉換及連線測試；少量 Activity 整合測試確認原生接線，真機另驗收輕震、握持、安全區與端到端貼上。具體先例及案例清單見 [Issue #11 的 Testing Decisions](https://github.com/DaDioDa/TalkToAgent/issues/11)。

### 行為與測試邊界

- [ ] 點一下開始 → 準備 → 真正收音 → 再點結束 → 有效定稿 → 傳送一次；不需按住，也沒有例行確認頁。
- [ ] 準備中主區停用，取消可用；取消後連線成功或麥克風啟動的晚回呼不能讓舊段重新收音。
- [ ] 收音中取消、切 App、返回退出及手動鎖屏，都不產生本次貼上；回來不自動續錄。
- [ ] 等待定稿時離開，晚到定稿不傳送；已送出後離開則不誤報為「未送出」。
- [ ] 45 秒計時包含準備；剩 5 秒雙震；到限正常收尾，等待有效定稿後僅傳送一次。
- [ ] 手動結束與到限同時發生、連點主區、取消與定稿回呼交錯，都不造成重複或取消後傳送。用可控制時間及回呼的測試覆蓋邊界，不僅靠真人等候秒數。
- [ ] 初始化失敗、無有效定稿、辨識失敗、定稿逾時均不傳送、不自動重試。
- [ ] 處理中主區、取消及次要入口依表停用；流程完成後依實際就緒條件恢復，而非一律顯示綠燈。
- [ ] 結果不明提示查看電腦；重連不補送、不清除警告，允許就緒後主動開始全新一段。
- [ ] 權限缺失、金鑰問題、未連線與驗證失效均有明確原因及修復入口。
- [ ] 原有連線、QR、金鑰與診斷功能仍可由新入口使用；Wi-Fi 單次傳送與藍牙工作階段行為未被 UI 改版默默改變。

### 真機與端到端

- [ ] 在既有支援手機與 Windows Receiver 驗證真實語音貼上；裝置範圍參照 [既有範圍](prototype-scope.md)，不把本規格解讀成已承諾全面支援所有手機。
- [ ] 左手持機且看電腦時，可辨認真正收音開始、正常結束與到限預警的震動；無提示音。
- [ ] 收音時不自動熄屏，結束／取消後恢復系統原有行為；手動鎖屏確實取消未送出內容。
- [ ] 全寬取消列左／中／右皆只取消，不觸發主操作；使用者實際握持檢查誤觸風險。
- [ ] 主操作與取消列在小可用高度、長狀態文字下仍可見且不跳位；設定／診斷捲動不影響主畫面定位。
- [ ] 手勢導覽與三鍵導覽皆不遮擋取消列，不侵犯系統操作區。
- [ ] 驗證「貼上操作完成」不被文案暗示為目標應用確實收到或指令已執行；結果不明情境不重複貼上。

以上皆是**待完成的正式版驗收**。執行時分別記錄自動測試、真機手感與端到端結果；環境阻擋或未實測項目必須明列，不以 mock、網頁操作或建置成功代替。
