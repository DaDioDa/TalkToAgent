# 增量規格：藍牙直連語音輸入

狀態：已實作藍牙通道並在 SM-F7410／Windows 配對設備上完成一次使用者確認的語音轉錄→藍牙傳送→貼上；本文件其餘驗收條件（尤其鎖屏 30 分鐘、斷線重連及 Windows 鎖定）仍待實機驗證。

本規格擴充 [家庭網路原型](spec-cross-device-voice-input.md)，不是現有功能的使用說明。原規格的語音辨識、繁體字形與貼上行為繼續適用；藍牙範圍、通道選擇與藍牙連線生命週期以本文件為準。領域詞彙見 [CONTEXT.md](../CONTEXT.md)，傳輸取捨見 [ADR-0001](adr/0001-direct-bluetooth-input.md)。

## 問題與目標

公司網路無法支援目前手機與 Windows Receiver 的區網連線。使用者已確認，公司允許藍牙資料連線及執行 Receiver。需要不依賴公司區網、IP 可達性或手機熱點的手機—電腦通道，而非繞過公司的裝置管理限制。

新增藍牙直連，只傳轉錄定稿、授權與操作結果等必要訊息，不傳麥克風音訊或 AI 回覆。兩端仍可各自上網；手機照常透過 Gemini 辨識，音訊仍會送往該雲端服務，不是完全離線或全程本機處理。

## 已確認的使用流程

1. 在手機手動選擇藍牙或原有 Wi-Fi 通道，同一時間只啟用一個通道；不得自動切換通道。
2. 第一版只驗收既有 SM-F7410 與 Windows Receiver，一次一支已授權手機連一台電腦。不提供多裝置同時輸入或多目標管理。
3. 首次先完成系統藍牙配對，再完成 Receiver 的應用層授權。僅有系統配對不代表有權觸發貼上。後續記住授權，允許撤銷；具體授權介面在可行性驗證後定案。
4. 使用者在前景主動連線，Android 顯示持續連線通知，提供中斷操作。通知所需權限及設定不可用時，要清楚說明，不能宣稱已符合背景使用條件。
5. 保留按住說話、放開後等待 Gemini 轉錄定稿並自動送出的流程，不新增每次送出前的確認步驟。
6. Receiver 將定稿寫入剪貼簿，對接收當時的目前焦點發出貼上操作，不自動按 Enter、不補空格或換行，也不還原原剪貼簿。
7. 貼上操作完成後才回報成功。不保證目標程式真的接受或顯示文字，也不代表指令已送出或執行。
8. 藍牙連線在一次操作後保持可用，允許後續多次口述，不要求每段重新配對或授權。

## 背景、斷線與輸入結果

| 情境 | 約定行為 |
| --- | --- |
| 切到其他 App 或手機鎖屏 | 維持藍牙通訊，不在背景錄音。取消仍在收音或等待定稿、尚未送出的本次輸入；遲到的辨識結果不得再觸發送出。 |
| 切背景時文字已送出 | 不承諾撤回。繼續記錄此次結果；無法確認時顯示「輸入結果不明」。 |
| 短暫斷線或走出範圍 | 自動重連原本選定的電腦，不切換 Wi-Fi、不改連其他電腦、不自動補送任何文字。 |
| 使用者手動中斷 | 停止重連；只有再次主動連線才恢復。 |
| 明確未送出或收到明確拒絕 | 保留最近定稿並說明原因；連線可用後由使用者主動重送，不建立自動補送佇列。 |
| 送出後沒收到結果 | 顯示「輸入結果不明」，保留文字，要求先查看電腦再決定是否重送。不得誤標為確定未輸入。 |
| Windows 鎖定或工作階段不可操作 | Receiver 拒絕貼上且不排隊，手機保留文字；解鎖後不自動補貼。若拒絕回報未能送達，手機仍只能顯示結果不明。 |
| 程序被系統終止或手機重開 | 不保證保留文字或持續連線；第一版不要求自動冷啟動恢復。一般切背景與斷線則需保留本次工作階段的最近定稿及其結果狀態。 |

「輸入就緒」仍需同時滿足已授權連線與語音辨識必要條件。已知接收端不可輸入、斷線或辨識條件缺失時不得顯示就緒。藍牙已連線不等於保證此次辨識或貼上成功。

## 授權、安全與資料保留

- 採系統安全配對的連線，並另行驗證應用授權；不得因 UUID、裝置名稱或已配對狀態相符，就接受任意手機輸入。
- 初次授權需由使用者明確確認或驗證；保存的授權必須可撤銷。重連不得繞過授權檢查。
- 逐字稿只保留在本次 App 工作階段，不建立磁碟歷史、持久待送佇列或文字日誌。授權資料的保存與逐字稿保存是不同概念。
- 原有 Wi-Fi 通道保留既有安全限制：`ws://` 配對碼不是傳輸加密，仍只適用可信任家庭 LAN。本次不使該通道變成可在公司網路正式部署的方案。
- 不使用 insecure RFCOMM 作為安全連線失敗時的自動降級方案。Windows 鎖定偵測及貼上前檢查失敗時不得假報成功；可操作性檢查不能消除焦點或工作階段在檢查後變化的競態。

## 技術方向與整合邊界

### 已選方向

- 使用 Bluetooth Classic 的安全 RFCOMM 串流，Android 主動連線，Windows 提供服務；不使用藍牙 PAN/IP 網路共享。
- Windows 優先保留現有 Python Receiver。Python socket 之外仍需處理服務註冊／探索、安全設定及服務生命週期。
- 如需原生輔助程式，必須作為 **Windows Receiver 的內部元件**整合配送／安裝、啟動、關閉與故障回報。使用者不需另外安裝、手動啟動或設定第二套工具；不強制內部只能有單一程序。
- Android 將藍牙連線生命週期與畫面、單次語音辨識分離。採 `connectedDevice` 前景服務方向，在使用者可見操作時啟動，支援持續通知與背景通訊；這不是永不斷線的保證。
- 既有 Wi-Fi 功能需保持可用，但本次不要求把它同步改成持久連線或提供背景保活。

### 實作前需驗證／定案

以下為工程驗證項目，不是已完成的能力或使用者承諾：

- Python RFCOMM socket、Windows 服務註冊／SDP、安全配對與 Android 自訂 UUID 的實際互通；必要時比較整合式 WinRT／原生元件。
- 授權憑證的產生、保存、撤銷及重連驗證，以及首次授權的具體操作。
- 串流訊息界線、長度上限與編碼驗證。沿用目前定稿上限 4096 UTF-8 bytes 的方向，但 RFCOMM 不能直接沿用 WebSocket 的訊息邊界。
- 多次操作的識別與結果關聯：不得將舊連線或上一段文字的回覆算到新操作。第一版不提供持久結果查詢或跨重啟的 exactly-once 保證；也不能阻止使用者明確手動再送一次相同文字。
- 重連退避、停止條件、通知權限、Bluetooth 權限及服務終止後的狀態清理。
- Windows 鎖定／工作階段不可操作的偵測與拒絕方式，以及檢查和貼上間仍可能存在的競態。
- 原有 `FinalTextTransport.authenticate(ipAddress, port, pairingCode)` 帶有 IP 假設；需要以不破壞 Wi-Fi 行為的方式分離通道設定，不能只加入另一個同名實作。

## 驗收條件

### 先做可行性驗證

在實際 SM-F7410 與 Windows 電腦上，先完成安全配對、服務探索、雙向文字與確認訊息；不先投入完整 UI。至少證明同一連線能完成多次傳送，以及鎖屏後仍能維持或恢復可用連線。若 Python 路線不可行，再驗證整合式輔助元件，不另交付一套工具。

目前只確認開發電腦有狀態正常的 Intel 藍牙介面，以及本機 Python 3.14.6 暴露 `AF_BLUETOOTH`／`BTPROTO_RFCOMM`。這些不是實機互通證據，也不構成其他 Windows／Python 版本的支援承諾。

### 功能與失敗情境

- 手機與電腦不在同一 LAN、彼此 IP 不可達時，藍牙仍可傳送定稿與回報；手機可透過自己的網路連 Gemini。
- 同一藍牙連線連續完成多段文字，每次操作至多觸發一次貼上；繁體中文、中英混用與上限邊界均正確，超限或無效訊息拒絕貼上。
- 在記事本與一般瀏覽器輸入框驗證貼上，不補空格、換行或 Enter；手機只在貼上操作完成後顯示對應結果。
- 未授權、已撤銷授權及非指定手機不能觸發貼上；重連仍需驗證授權。
- 手機鎖屏 30 分鐘後返回 App，不用重新配對／授權即可恢復使用；記錄是否中途斷線及恢復行為，不將自動重連當成全程從未斷線。
- 走離範圍再返回，能自動重連原電腦但不補送；通知或 App 手動中斷後不自動重連。
- 在收音、等待定稿、已送出待結果三個階段分別切背景，驗證取消界線、停止錄音與輸入結果不明狀態。
- 模擬電腦已貼上但確認訊息丟失：不得自動再貼，手機提示先查看電腦。
- Windows 鎖定時拒絕輸入；解鎖不補貼。程序終止後不從磁碟恢復逐字稿。
- 手動切換通道時不允許兩個通道同時輸入，不因切換而補送舊文字；原有 Wi-Fi 路徑維持原本行為與安全警告。
- 若使用輔助元件，從 Windows Receiver 的單一入口即可啟停，元件故障可見且不會假報就緒。

可自動測試協定解析、授權、結果關聯、無自動補送、生命週期取消及可替換貼上動作；真實無線互通、配對、安全設定、背景保活與 Windows 貼上效果必須另外做實機驗證，不能用 mock 通過取代。

## 不在本次範圍

- 原始音訊經藍牙傳送、AI 回覆回傳、本機／離線語音辨識。
- 背景錄音、通知列開始口述、多裝置同時輸入或自動跨通道切換。
- 斷線自動補送、持久逐字稿、跨程序重啟的結果查詢與去重保證。
- 自動 Enter／執行指令、任意目標程式的文字接收保證、管理員視窗及安全桌面的可靠輸入。
- Windows Receiver 以外需要使用者另外管理的藍牙工具。
- Wi-Fi 通道 TLS 升級、其他手機型號或其他桌面作業系統的支援承諾。
