## Agent Brief

**Category:** enhancement

**Summary:** 用短效單次 QR 連線邀請取代手動連線設定，支援 Wi-Fi／安全藍牙，並建立可撤銷的持久應用授權。

**驗證狀態：** 使用者已確認需求與驗收要求；程式碼及藍牙 API／文件核對已完成。尚未實作或驗證新的 QR／未配對裝置續接流程。實機驗收需要使用者配合系統確認，不得將自動測試通過當作全部驗收完成。

**Current behavior:**

- Android 手動輸入 Wi-Fi IP、port 與 Receiver 臨時配對碼；藍牙則手動選擇已系統配對的電腦並輸入臨時碼。
- 藍牙首次應用授權還需 Windows 主控台輸入 yes。現有藍牙會記住手機位址，但仍使用 Receiver 當次臨時碼驗證，不能視為完整的跨重啟持久授權。
- Receiver 已有 Python WebSocket 與安全 RFCOMM 通道，未提供 QR 產生或 Android 掃描功能。
- 以上為程式碼核對；尚未實測新的 QR 或未配對裝置續接流程。

**技術核對與實機驗證界線：**

- Android 可使用已知 MAC，無須先做裝置搜尋；`createBond()` 為非同步，須等待指定裝置的 `BOND_BONDED` 才續接。Android 12+ 配對／連線須有 `BLUETOOTH_CONNECT`；其他權限依實際 API 使用逐項確認，不因掃 QR 而假定必須做藍牙 discovery。
- 目前 Windows wildcard listener 的 `getsockname()` 不可直接假定為 QR 所需的實體位址。須取得實際 radio 位址，確保邀請目標、listener 與 SDP 一致；全零或無法取得的位址不可產生邀請。
- 首次實機驗證須涵蓋未配對手機、Android／Windows 系統確認及成功續接。若平台行為無法滿足契約，回報限制，不能以已配對裝置成功或 mock 測試替代。
- 依據：[Android createBond](https://developer.android.com/reference/android/bluetooth/BluetoothDevice#createBond())、[連線指南](https://developer.android.com/develop/connectivity/bluetooth/connect-bluetooth-devices)、[權限](https://developer.android.com/develop/connectivity/bluetooth/bt-permissions)、[Windows SOCKADDR_BTH](https://learn.microsoft.com/en-us/windows/win32/api/ws2bth/ns-ws2bth-sockaddr_bth)、[BluetoothGetRadioInfo](https://learn.microsoft.com/en-us/windows/win32/api/bluetoothapis/nf-bluetoothapis-bluetoothgetradioinfo)。

**Desired behavior:**

### 連線邀請與首次使用

- Windows 依 Receiver 當前啟動模式顯示一份單通道 QR。使用現成 Python 套件，優先驗證 Segno 的標準 QR；不自行寫編碼器、不引入 Node runtime。
- 使用版本化 TalkToAgent 專用 URI，明確限定合法版本、通道、目標與必要欄位。格式及解析須具備跨平台測試；不建立外部相機／Deep Link 入口。
- Android App 內掃描有效邀請後立即嘗試連線與應用授權，不再要求確認目標。不開啟任意 URI，也不從 QR 執行指令。
- 未完成系統藍牙配對時，App 開啟系統配對流程，成功且邀請仍有效後自動續接。不得繞過系統確認或降級為 insecure RFCOMM。配對取消時停止嘗試並要求重掃；過期要求 Windows 產生新邀請。不撤銷已完成的系統配對。
- 邀請有效期 10 分鐘，由 Receiver 判定；僅成功取得應用授權時原子消耗一次。未成功者可在期限內重試。成功驗證邀請取代原 Windows 主控台 yes；必須警告持有有效 QR 者可能搶先授權。
- Android 完全移除手動輸入 IP、port、授權碼及手動選擇藍牙裝置的連線入口。掃碼不可用時清楚阻止並提供權限、終端尺寸／縮放及重顯示等導引，不另設手動或 QR 圖片備援。

### 授權及重連

- 邀請與持久應用授權分離。兩端安全保存獨立授權資料，直到使用者撤銷；重連不得重用已消耗的邀請秘密或直接在網路上傳送可長期重用的秘密。
- 一台 Receiver 只授權一支手機。Wi-Fi、藍牙各自掃碼取得權限，不自動跨通道授權；追加通道須驗證仍為原手機。
- 更換手機前，Windows 必須明確撤銷原手機，終止其連線並使兩通道既有授權失效，才允許新手機取得邀請授權。
- App 重啟後顯示原電腦與已授權通道，由使用者按「連線」恢復。不新增開機自動連線或開啟 App 即自動連線。既有藍牙工作階段的斷線自動重連仍保留；手動中斷後不自動重連。
- 成功授權回覆遺失時，原手機須有可恢復路徑；不得因此讓第二支手機重用邀請，亦不得自動補送任何文字。設計中須明確描述授權持久化、消耗及回覆之間的失敗處理。

### 主控台及目標變更

- Receiver 主控台提供產生新邀請與撤銷授權的操作，不必重啟。新邀請立即使舊的未使用邀請失效；不自動刷新或持續開放授權。
- 已有授權手機時，新邀請只能供原手機追加通道或更新資料；不同手機必須先撤銷再重新授權。
- Wi-Fi 有多個候選位址時，由 Windows 使用者選擇後產生單目的位址 QR，不由手機自動試連。
- 藍牙只有一個可用本機介面時直接使用；多個時由 Windows 主控台選擇，QR 與 listener／SDP 綁定同一介面。無可用介面時清楚阻止啟動，不產生無效邀請。
- 原電腦 IP 改變可為原手機產生短效單次更新邀請；掃描後驗證原電腦及原手機身分才更新，不撤銷授權、不引入自動探索。
- App 已連線時不能掃描新邀請；須先結束本次輸入並主動中斷。已送出但無法確認的文字仍顯示「輸入結果不明」，不能因切換而抹除或補送。

**Key interfaces:**

- `FinalTextTransport`／`WebSocketFinalTextTransport`：由手動 IP 與臨時碼驗證演進為邀請授權及後續身分驗證；維持既有單次文字傳輸行為，不順帶加入 Wi-Fi 背景保活。
- `BluetoothFinalTextTransport`／`BluetoothConnectionService`：支援從邀請指定安全藍牙目標、系統配對續接及持久授權重連；保留通知、手動中斷與無自動補送契約。
- `MainActivity`：掃描、系統配對狀態與已授權目標連線入口；未知或非法 QR 不得修改現有授權或假報輸入就緒。
- Receiver 的 WebSocket／RFCOMM 授權邊界：共用邀請期限、單次消耗、原手機識別、通道權限與撤銷語意；不得將授權決策混入貼上實作。
- 新增可獨立測試的邀請編解碼、授權狀態及終端 QR 顯示邊界。QR 套件只編碼顯示，不負責授權安全。

**Acceptance criteria:**

- [ ] SM-F7410 掃描 Windows 終端 QR，可分別完成 Wi-Fi 與藍牙首次授權，無手動輸入連線資料及主控台 yes。
- [ ] 未配對藍牙裝置可經系統確認完成配對並續接；取消、失敗及配對後邀請過期皆依規格處理，不使用不安全連線降級。

- [ ] 並行申請只能授權一支手機；無效申請不消耗邀請；成功回覆遺失可恢復但不能被其他手機重用。
- [ ] App 與 Receiver 重啟後仍可由原手機按「連線」恢復，無需重新掃碼；已消耗的邀請不可用作新的首次授權。
- [ ] 撤銷後兩通道的舊授權、現有連線與重連均不能再觸發新的貼上；不能冒充原手機追加通道或替換電腦位址。
- [ ] 連線中不能掃新邀請；中斷或切換不補送，結果未知時仍顯示「輸入結果不明」。
- [ ] 相機／藍牙權限拒絕、終端太窄、目標不可達及錯誤 QR 均有清楚導引，不假報輸入就緒。
- [ ] 實機驗證包含實際 URI 長度、Windows 終端字型／縮放與 QR 邊界；不能只用編碼單元測試代替掃描成功。
- [ ] 單一／多個／無可用藍牙介面的選擇與錯誤路徑有測試；不將 wildcard 全零位址編入 QR，邀請與實際 listener／SDP 目標一致。
- [ ] 邀請及授權秘密不寫入一般日誌、逐字稿歷史或 QR 圖檔；主控台提示不要分享 QR 或將其輸出保存為日誌。
- [ ] 既有語音、繁體文字、貼上操作完成、Windows 鎖定拒絕輸入、無自動 Enter／無自動補送等行為不變。
- [ ] 更新使用說明與安全警告，清楚區分系統藍牙配對、應用授權、連線邀請及輸入就緒，移除已被取代的手動設定指引。

**Out of scope:**

- 自行實作 QR 編碼器、Node runtime、指定必須使用 qrcode-terminal。
- 多手機授權／同時輸入、多目標管理、自動跨通道切換或網路自動探索。
- 外部相機入口、QR 圖片備援、Wi-Fi 背景保活或開機自動連線。
- Wi-Fi TLS、公司或公共網路部署承諾。現有 ws:// 的轉錄文字仍未加密，QR 與持久授權不改變此限制，也不構成抵禦主動中間人的承諾。
- 改變 Gemini 語音流程、持久逐字稿、自動補貼或自動 Enter。
