# 短效 QR 邀請與持久簽章身分分離

#9／#10 要求掃碼取代手動連線設定，同時保留跨重啟授權與可撤銷的單手機限制。使用者已確認以雙端 P-256 簽章及隨機 challenge 驗證身分，Android 私鑰放 Keystore、Windows 私鑰以目前使用者 DPAPI 保護；不將 QR 秘密升格為長期憑證，也不以 MAC 位址作手機身分。

授權與邀請消耗必須先原子持久化再回覆，手機先保存 pending 目標與 pin，成功回覆遺失可由原身分恢復。撤銷與貼上開始共用排序邊界，避免仍存活的舊會話繞過撤銷。Receiver 使用單程序鎖確保記憶體中的邀請及撤銷生命週期一致。

沿用 ADR-0001 的 Python Receiver／安全 RFCOMM，不引入 Node runtime；使用成熟 Python QR 套件及密碼學套件，避免自行實作編碼器或密碼學。此決策取代手動 IP／port／臨時碼入口，不改變通道由使用者主動選擇、不自動切換／補送及系統配對不等於應用授權。QR 不加密 ws://，亦不承諾抵禦主動中間人；新流程仍需實機驗收。

精確編碼與失敗語意見 [授權協定](../authorization-protocol.md)。
