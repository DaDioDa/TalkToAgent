# 以安全 RFCOMM 增加不依賴公司區網的輸入通道

公司網路無法支援目前手機與 Windows Receiver 的區網互通，而使用者已確認允許藍牙資料連線及執行 Receiver。因此新增 Bluetooth Classic 安全 RFCOMM 直連，傳送轉錄定稿及必要的授權／操作結果；保留 Wi-Fi 手動選擇，但不自動切換或補送。這不改變手機使用 Gemini 雲端辨識的流程，也不使原有未加密 Wi-Fi 通道適用於公司網路。

相較藍牙網路共享，直接 RFCOMM 不需建立 IP 通道；相較 BLE GATT，它的雙向串流更貼合此處的文字／結果交換，避免另設特徵值與分段重組流程，代價是需要處理 Windows 的服務註冊、安全設定與兩端持久連線生命週期。系統配對之外仍需應用授權，避免把其他已配對用途誤當作貼上權限。

Windows 優先沿用 Python Receiver；必要時允許原生輔助元件，但必須整合在 Receiver 的配送／安裝、啟停及故障回報內，不能要求使用者另外管理工具。此決策確認需求及技術方向，不宣稱 API 存在就代表實機互通；應先在 SM-F7410 與實際 Windows 藍牙介面驗證 RFCOMM、安全配對與鎖屏保活，再投入完整介面。若驗證推翻此方向，需更新本決策，不能默默降級到不安全連線或 IP 網路共享。

完整範圍與驗收條件見 [藍牙增量規格](../spec-bluetooth-input.md)。
