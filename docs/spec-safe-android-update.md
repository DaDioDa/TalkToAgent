# Android 安全更新入口

狀態：已實作；本機自動測試、獨立雙軸審查及隔離模擬器驗證通過，未用使用者手機試裝。使用方式見 [安全更新入口](../tools/android/README.md)，本次證據見 [驗證報告](../.scratch/safe-android-update/validation.md)。這是本專案部署工具，不改 App、Receiver 或應用授權協定。

## 目的與術語

避免把「更新手機上的既有 App」誤做成安裝另一個包名的空白 App，或在套件身分不明時繼續操作。

- **更新目標**：ADB 裝置、Android 使用者及完整套件名三者組成的既有安裝。
- **套件身分**：從 APK 實際內容取得的 applicationId 與經驗證的完整簽署者集合；檔名、App 顯示名稱及輸出目錄不是身分。
- **應用授權**仍依 `GLOSSARY.md`：Windows Receiver 的貼上權限，與 APK 簽章／安裝許可不同。本文件的部署術語不加入產品領域詞彙表。

## 已確認決策

1. 只提供本專案的既有安裝更新，不提供首次／並存安裝模式。
2. 預設辨識目前 Android 使用者；其他 user 必須明確指定。
3. 只有唯一符合本專案的候選才可自動選定。有歧義或無法確認時停止，列出可採取的明確指定方式，不猜測。
4. 先選定目標，再依該套件名建置；不接受任意預先提供的 APK 作為本版入口。
5. 新舊 APK 均須驗簽成功，完整簽署者集合完全相同。第一版不處理以不同簽章歷史／輪替來放行的情況。
6. 檢查通過便更新，不追加互動確認；另提供僅檢查模式，完成檢查但不安裝／啟動。
7. 更新且核對成功後，自動啟動所選 App 一次。啟動失敗不重装、不補跑安裝，也不宣稱 App 已在前景。
8. 接受 Android 同包名程式碼跨使用者／profile 共用的正常更新行為，並明確揭露此影響。
9. 接受檢查式防護，不宣稱原子 update-only；觀察到目標變動即停止。
10. 開發及自動驗證不以使用者手機實際安裝或其他變更作為測試手段。

## 對外入口與範圍

提供 Windows PowerShell 可執行的單一更新入口，支援按需明確指定裝置 serial、Android user ID、完整套件名，以及僅檢查模式。一般更新的前置操作可讀取套件 metadata／既有 APK、建置及寫本機暫存，不讀取 App 私人資料、Keystore 私鑰或使用者金鑰。

只辨識本專案既有的兩個套件：

| 套件 | 對應建置 |
| --- | --- |
| `com.example.talktoagent` | debug，明確使用 `bluetoothTestApp=false` |
| `com.example.talktoagent.bluetoothdebug` | debug，明確使用 `bluetoothTestApp=true` |

診斷包、instrumentation 套件、名稱部分符合的包不是候選。未指定項目可自動辨識，但不能因查詢失敗就當成不存在、或悄悄改选另一個目標。多裝置／多套件造成多候選時停止。明確指定不存在的目標也停止，不能回退到自動選別的目標。

目前使用者只決定查找範圍，不代表只讀到 user 0。user ID 必須可驗證，無權讀取時停止；不嘗試繞過工作設定檔／安全資料夾的權限。

## 更新流程與失敗邊界

1. 驗證工具鏈、參數及裝置狀態；找出唯一目標。所有裝置命令均綁定選定 serial，需要 user 的操作均明確傳入 user。
2. 讀取並記錄目標快照；取得既有 APK 的實際包名、版本、簽章與內容指紋。若無法完整取得所需資訊，或遇到尚未支援的 APK 形式，明確停止。
3. 以選定目標的建置設定產生 APK。使用隔離的建置／產物位置，避免覆蓋一般建置或先前交付的 APK；不修改受版控的 applicationId 或 Gradle 設定来切换包名。
4. 檢查新 APK：實際包名符合目標、APK 驗簽成功、完整簽署者集合相同、版本不低於既有版本且裝置符合 SDK 要求。同 versionCode 的 debug 更新可以執行。簽章資料不是只取第一筆，也不把 source stamp 當 App signer。
5. 安裝前重新核對裝置、目標使用者、既有安裝與身分快照，以及待安裝產物。自動選定的目前使用者已切換、目標消失或觀察到其他變動時停止。僅檢查模式至此結束，不安裝、不啟動。
6. 使用保留既有資料的替換安裝，精確指定 serial／user。參數以真正的 argv 傳遞，不把 `-r --user 0` 合為一個字串。不得用卸載、清資料、降版旗標、換包名、放寬簽章要求或自動重試來處理失敗。
7. 確認安裝結果，核對目標目前的包名、版本、簽章及 APK 內容符合本次產物，然後啟動一次。安裝結果不明或安裝後核對失敗時，報告當前狀態、停止後續啟動；不假裝能回滾已完成的更新。
8. 回報選定目標、產物識別、已完成的步驟與失敗原因。僅清理本次建立的暫存資源，不清除原 App 資料，不自動修改權限或其他裝置設定。

每個外部程序的 exit code 及必要結果都需檢查；前一查詢失敗不能被後一成功命令掩蓋。錯誤訊息應指出阻擋原因及安全的下一步，而非建議卸載原 App。

## 平台限制

- 同包名 APK 的程式碼由裝置上的使用者／profile 共用。`--user` 不提供 binary 隔離；其他已安裝同包名套件的 profile 會使用新版。各使用者的 App 資料仍分離。無權查某個 profile 不能宣稱那裡沒有安裝。
- 檢查及安裝之間仍有競態。操作期間應避免另行卸載、更新或切換使用者；重新核對只拒絕可觀察的變動，不聲稱鎖住整個裝置。
- Package Installer 的 inherit-existing／partial install 不是一般版本升級的通用原子 update-only 替代方案，本工具不以它聲稱不存在競態。
- 工具的保留資料承諾是不用卸載／清除等破壞性安裝手段；不能保證新 App 本身的所有資料遷移行為。也不以複製 App 私人資料／金鑰做備份來繞過限制。
- 僅檢查模式可建置、讀取 APK 及建立本機暫存，但不能安裝、啟動、授權或變更裝置設定。

平台參考：[Android 多使用者](https://source.android.com/docs/devices/admin/multi-user)、[SigningInfo](https://developer.android.com/reference/android/content/pm/SigningInfo)。官方資料不等於已在本機 Samsung 驗證。

## 驗收與測試邊界

測試透過安全更新的對外入口，控制外部命令邊界（ADB、Gradle、APK metadata／驗簽工具），觀察輸出、退出結果與是否真的提出安裝／啟動命令。替身不能代替目標選擇、身分核對或更新協調邏輯；不直接測 private handler，也不建立平行的假流程。

必須覆蓋：

- 唯一正式包／Bluetooth Debug 包選對建置設定；實際包名仍須核對，不能只信 build flag。
- 零候選、多候選、明確指定不存在／不允許的目標、診斷包與部分名稱不能誤選。
- 查詢失敗、裝置未授權／不可用、user 權限不足或無法辨識時，在安裝前失敗。
- 新舊 APK 包名不符、驗簽失敗、簽署者集合不符／缺漏、多 signer 只匹配其中一枚時拒絕；不能混入 source stamp。
- APK 路徑含空白／中文，以及安裝參數分開傳遞。
- 版本降低、SDK 不符、建置失敗及產物不可驗證均拒絕；同版號 debug 可更新。
- 選定後目標消失、APK／使用者等快照變動、待安裝產物被替換時停止。
- 僅檢查模式不安裝／啟動；正常更新指定正確 serial／user，成功核對後只啟動一次。
- 安裝失敗／結果不明、安裝後身分不符或啟動失敗：正確回報，無卸載／清資料／自動重裝或重試。
- 故意切斷包名或簽章 guard，對應負向測試必須變紅，再恢復正式檢查。

以不連裝置的自動測試為主；如做原生安裝 smoke，只能選明確隔離的任務模擬器，不能操作使用者手機，且必須區分替身與真實安裝證據。

## 非目標

首次／並存安裝、任意外來 APK、簽章輪替支援、App 功能變更、套件改名遷移、私人資料備份、整套 CI、新的全域 skill／代理模型護欄，以及與本次安全更新無關的既有文件修訂。
