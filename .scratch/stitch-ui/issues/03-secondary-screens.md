# 03: 統一裝置連線與次要頁面風格

**What to build:** 使用者由新版首頁進入裝置連線、設定、QR 掃描、金鑰、權限說明、最近定稿詳情及診斷時，看到一致的深色原生介面，並能完成原有操作。長內容、大字體或鍵盤彈出時，欄位、回饋與提交／返回操作仍可使用。

**Blocked by:** 01 — 還原語音首頁與既有操作。

**Status:** implementation-complete（human-validation-pending）

實作／測試／截圖見 [Ticket 03 報告](../reports/ticket-03.md)。未勾選的複合條件仍包含硬體、系統人機流程或待真人驗收，並非宣稱其已端到端通過。

## 規格界線

依《TalkToAgent：Stitch 深色原生 UI 還原規格》的「裝置連線與次要頁面」「視覺與原生實作」「版面與可及性」實作；來源與領域文件由本功能索引提供。

沿用前置票已建立的共用樣式、元件與首頁入口，依語音首頁畫稿延伸未提供畫稿的次頁，而不是另創一套設計。這些流程使用現有資料與操作，不需要辨識預覽或音量功能完成後才能接手。

範圍為 App 自有畫面；Android 系統權限及系統藍牙配對仍使用系統介面。保留傳輸／授權協定、憑證與既有行為，不新增帳號、持久歷史、手動 IP 或永久配對碼流程。

## Acceptance criteria

### 裝置連線與 QR

- [ ] 從「裝置連線」分頁可查看真實電腦、已知通道、連線／操作狀態並返回語音首頁；尚未連線、連線中、拒絕與失效等狀態有真實回饋與下一步，不因換頁或美化顯示成輸入就緒。
- [ ] QR 邀請掃描、恢復既有應用授權、藍牙／Wi-Fi 通道選擇及主動中斷均接到原有流程；「連線邀請」「應用授權」「系統藍牙配對」清楚區分，掃碼成功不冒充授權或系統配對完成。
- [ ] QR 掃描的 App 自有說明、按鈕及回饋套用一致風格；相機畫面、掃描結果、取消／返回、權限拒絕及無效邀請仍按既有流程運作。
- [ ] 不自動切換通道、補送、重送或因回到畫面而自動開始收音；Wi-Fi 單次連線、藍牙工作階段與應用授權恢復行為維持不變。

### 設定、定稿與診斷

- [ ] 設定包含 Gemini 金鑰、麥克風權限及診斷／手動測試，且均能完成實際操作及返回；低頻功能維持在次頁，不重新擠回首頁。
- [x] 金鑰輸入遮蔽、已存金鑰不回填，儲存及清除接到既有安全儲存流程；狀態刷新不清空正在輸入的金鑰或診斷草稿，也不暴露已存憑證。
- [ ] 權限說明清楚呈現缺少條件與對應修復方式；請求／拒絕／修復後的狀態正確，返回 App 後由使用者主動開始，不自動收音。
- [x] 最近轉錄定稿詳情支援空態、全文閱讀與手動複製；不新增歷史、不把查看／複製變成再次傳送，也不把未確認結果說成目標程式已收到。
- [x] 診斷／手動測試保留獨立的一次性送出；未就緒或操作忙碌時無法送出，狀態更新不破壞草稿。手動測試不冒充語音定稿，其結果不附到錯誤的定稿上。
- [ ] 準備、收音、等待定稿及傳送時，次要入口維持停用；各頁返回與流程回饋不破壞首頁的操作狀態。升級後既有設定與應用授權仍可使用，不要求清資料或卸載。

### 共同視覺、可及性與驗證

- [ ] 全部 App 自有次頁共用首頁的深色、色彩角色、卡片、字級、圓角與操作樣式；系統淺色模式或動態色不改色，不新增頭像、假數值或無功能入口。
- [ ] 各頁內容可捲動，較寬視窗限制內容寬度；320dp 小視窗、2.0 倍字體、長原因／長定稿、鍵盤、挖孔及手勢／三鍵導覽下，欄位、提交、返回與修復入口均可到達，必要文案能完整閱讀。
- [ ] 互動目標至少 48dp，圖示與欄位有可理解的 TalkBack 名稱／標籤，焦點順序符合操作流程；成功、等待與錯誤不只以顏色區分。
- [ ] 補上原生頁面／流程回歸測試，涵蓋入口與返回、阻塞原因、授權恢復、QR 取消／失敗、金鑰安全、草稿保留、定稿複製、手動測試可用性及語音忙碌時的入口限制。
- [x] 執行相關單元、原生整合測試、建置及 lint，保留既有連線生命週期與授權測試；不將單純換皮當作改變協定行為的理由。
- [ ] 留存裝置連線、設定、金鑰、權限、定稿、診斷、QR 掃描及代表性空態／錯誤回饋的原生截圖；確認與首頁風格一致，記錄小視窗、大字體、鍵盤與系統安全區的檢查結果。
- [ ] 實機走過 QR／系統權限、連線／授權恢復、金鑰管理、定稿複製及手動文字到 Windows 的流程。交付測試結果、截圖及未實測項目；缺裝置或服務時明列待驗收，不以畫面可點或建置成功代替端到端完成。
